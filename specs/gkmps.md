# GKMPS — correlated-noise Δ-summation (Ghazi, Kumar, Manurangsi, Pagh, Sinha, ICML 2021)

Source: arXiv:2109.13158v1 (sha256 prefix d64ad4568f4c4f97, downloaded 2026-10-30).

## Protocol (pure shuffle model)
- User i holds x_i ∈ {0..K} after the same adjacent-grid unbiased quantisation as PW-Sum. Here
  the user sends **x_i + 1 ∈ {1..K+1}** (always one input message, so "x = 0 ⇒ no message" leaks nothing); hence
  **Δ = K + 1** and the analyzer subtracts N.
- Algorithm 1 (CorrNoiseRandomizer): user i also samples z_i^{+1}, z_i^{-1} ~ D_central/N and, for every noise atom
  s ∈ S, z_i^s ~ D_s/N, and sends z_i^{±1} copies of ±1 and z_i^s copies of every element of s.
- Shuffler: uniform permutation of all messages. Analyzer (Algorithm 2): sum of all messages, minus N.
- Visibility: shuffler sees message counts/sources; analyzer sees the shuffled multiset. **Noise is generated by users.**

## Privacy (with theorem numbers)
- Observation 7: shuffle protocol is (ε,δ)-DP iff CorrNoiseCentral (Algorithm 3) is (ε,δ)-DP in the central model.
- **Theorem 8** (generic): with C a right inverse of Ã, if D̂-noise addition is (ε1,δ1)-DP for Δ-summation and
  (D̃_s)-noise addition is (ε2,δ2)-DP for the [0 c2 … cΔ]-linear query, then with D_central = NB(1, e^{-ε*/Δ}),
  D_{−1,+1} = D̃_{−1,+1} + D̂, D_s = D̃_s otherwise, the protocol is (ε*+ε1+ε2, δ1+δ2)-DP.
- **Theorem 2** (recipe, proof in Sec. 4.5): ε* = (1−γ_G)ε, ε1 = ε2 = min{1, γ_G ε}/2, δ1 = δ2 = δ/2,
  D̂ = NB(r̂, p̂), p̂ = e^{−0.2ε1/Δ}, r̂ = 3(1 + ln(1/δ1)) (Theorem 10, corrected statement cited by the paper);
  D̃_s = NB(r_s, p_s), p_s = e^{−0.2ε2/(2 t_s)}, r_s = 3(1 + ln(|S|/δ2)) (Corollary 11).
- **Theorem 12** (proof in SM D.3): S = {{−1,+1}} ∪ {{i, −⌊i/2⌋, −⌈i/2⌉} : i ∈ {−Δ..−2, 2..Δ}};
  Γ = Δ·⌈1 + log2 Δ⌉; t_{−1,+1} = Γ; t_s = ⌈Γ/m⌉ for the two atoms with |i| = m.
- Preconditions: Theorem 10 needs ε1, δ1 ∈ (0,1) (true: ε1 ≤ 1/2); Theorem 2 states 0 < ε ≤ O(1) — we use ε ∈ {0.1..5};
  for ε where γ_G ε > 1, ε1 = ε2 = 1/2 is still valid for Theorems 8/10/11 (they only need ε_i ∈ (0,1)).
- Neighbouring relation: replace-one (paper Sec. 2), same as ours.
- **Trust/collusion**: noise is local; colluding users that reveal their own noise shares remove their part of every
  infinitely divisible noise. Not robust to user–analyzer collusion in the sense of PW-Sum's full-view DP.

## Estimator and analytic MSE
Integer layer: sum of messages − N − Σx̃ = Z⁺ − Z⁻ with Z^± = Σ_i z_i^{±1} ~ NB(1, p), p = e^{−ε*/Δ}; every zero-sum atom
contributes 0 exactly. Hence error_int ~ DLap(ε*/Δ), Var = 2p/(1−p)² (Observation 5).
Real (X_max = 1, grid 1/K): MSE = 2p/((1−p)² K²) + Σ_i f_i(1−f_i)/K² ≤ 2p/((1−p)² K²) + N/(4K²).

## Communication (Observation 6, exact expectation)
E[messages/user] = 1 + (1/N)[2E D_central + Σ_s |s| E D_s], E NB(r,p) = rp/(1−p), |{−1,+1}| = 2, other atoms 3,
E D_{−1,+1} = E D̃_{−1,+1} + E D̂. Message alphabet {−Δ..Δ}: ⌈log2(2Δ+1)⌉ bits (paper: ⌈log Δ⌉+1).
Bytes (analytic, ECIES like PW-Sum): ℓ = 48 + ⌈bits/8⌉ per message, counted on both links (user→shuffler and
shuffler→analyzer), divided by N.

## Parameter selection (formulas only)
For target V = 2(1+γ)/ε²: choose K ≥ 1 and γ_G ∈ (0,1) minimising expected bytes subject to the worst-case MSE
2p/((1−p)²K²) + N/(4K²) ≤ V; γ_G grid 1e-4..0.999 (log-spaced, 400 points) × all K up to the point where the
quantisation term alone forces infeasibility or the message floor exceeds the best. Report the best-found point; if no
(K, γ_G) meets V, report the minimum achievable MSE.

## Simulation shortcut (equivalence proof)
Sum of all messages = Σ_i (x̃_i + 1) + Σ_i (z_i^{+1} − z_i^{−1}) + Σ_s (Σ_i z_i^s)·Σ_{m∈s} m, and Σ_{m∈s} m = 0 for
every atom. By infinite divisibility Σ_i z_i^{±1} ~ NB(1,p) independently, so estimate − Σx̃ =d Z⁺ − Z⁻, which we
sample directly (difference of two geometric variables). Quantisation is simulated per user as for PW-Sum.
Message counts are random; communication uses the exact expectation (no sampling).

## Deviations from the paper
- Users send x+1 (Δ = K+1) instead of "send x if x ≠ 0" (costs at most one bit/message and one message).
- We use the analytic recipe of Theorem 2, NOT the paper's numerical parameter search (Sec. 5 / SM), which the paper
  reports to be much cheaper. Our communication numbers are therefore an upper bound for GKMPS.
- Real summation through our quantiser instead of the paper's Theorem 1 construction.
