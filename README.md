# PW-Sum: experiment code

Code, parameters and aggregated results for the experiments of
**"PW-Sum: Robust Differentially Private Summation via Position-Weighted Augmented Shuffling"** (ICDE 2027 submission).

In PW-Sum, a Shuffler adds correlated, position-weighted dummy messages, so that the anonymous histogram seen by the Server is
$(\epsilon,\delta)$-DP while the sum estimate has near-central error. This repository reproduces the figures and tables of
Section V (Experiments): utility, robustness to collusion and poisoning, cost, ablations, and a database workload.

## Layout

| Path | Content |
|---|---|
| `src/pwexp/` | Position weights and parameter rule (`pw_core_task.py`, `pw_search.py`), exact sampler and integerization (`pw_sampler.py`), baselines CDP, LDP, GKMPS, BBGN, ID-Sum and Prio3Sum with discrete Laplace noise (`baselines.py`), synthetic data (`synthetic.py`), paths (`paths.py`) |
| `scripts/` | Experiment drivers, plotting scripts and shell pipelines (table below) |
| `rust/` | Message path with HPKE (RFC 9180) and Prio3Sum (`libprio` 0.18.1); commands `pw4`, `prio2`, `dbq_pw`, `dbq_prio` |
| `specs/` | One specification per baseline: theorems used, parameters, estimator, deviations |
| `params/` | Selected PW-Sum parameters with the 256-bit interval-arithmetic checks |
| `results/` | Aggregated results read by the plotting scripts (no raw data) |
| `figures/` | The figures of Section V, regenerated by `scripts/make_figures.sh` |
| `DATA.md` | Datasets: sources, checksums and cleaning rules |

## Requirements

- Python 3.12: `pip install -r requirements.txt`
- Rust (stable): `cd rust && cargo build --release`; dependency versions are fixed by `Cargo.lock`
- Datasets (only for rerunning experiments): see `DATA.md`; set `PWSUM_DATA` to the dataset directory (default `./data`)

Our runs used a server with two Intel Xeon Gold 6530 CPUs (128 hardware threads) and 503 GiB of memory under Ubuntu 24.04.
Most drivers use a process pool; the number of workers is a command-line option or a constant at the top of the script.

## Quick check (no datasets, a few minutes)

```bash
python scripts/smoke_test.py      # parameter rule, interval checks, sampler and integerization invariants, baselines, Rust binary
bash scripts/make_figures.sh      # regenerates figures/ from results/
```

## Reproducing the experiments

Run from the repository root. Times are wall-clock on the server above.

| Part of Section V | Commands | Output | Time |
|---|---|---|---|
| Data (Table I) | `bash scripts/run_m0.sh` | `$PWSUM_DATA/*/processed`, `results/m0_data_summary.csv` | ~10 min |
| Parameters (Table II) | `python scripts/s9_params_radius.py`; `python scripts/r5_full_enum.py` | `params/pw_params_radius.*`, `results/params_full_enum.csv` | ~15 min |
| Utility (V-B) | `bash scripts/run_pu1.sh`; `bash scripts/run_pu2.sh`; `python scripts/pu_decomp.py` | `results/pu/*` | ~3 h |
| Baseline self-checks | `python scripts/m5_selfcheck.py` | `results/m5/selfcheck.csv` | ~10 min |
| Robustness (V-C) | `python scripts/r1_collusion.py`; `python scripts/f_fix.py`; `python scripts/r1b_collusion_k2.py`; `python scripts/r2_poison.py`; `python scripts/r3b_protocol.py` | `results/robust*` | ~1 h |
| Cost (V-D) | `python scripts/s11_cost_params.py`; `python scripts/c2_comm.py`; `python scripts/c1_sampler.py`; `python scripts/c3b_full_run.py`; `python scripts/c4_same_schedule.py` | `results/cost/*`, `results/c4_same_schedule.jsonl` | ~12 h |
| Ablation (V-E) | `python scripts/r4_ablation.py`; `python scripts/r4b_ablation.py`; `python scripts/beta0_small_k.py` | `results/ablation*`, `results/m6/` | ~1 h |
| Database workload (V-F) | `python scripts/dbq_run.py`; `python scripts/dbq_wcheck2.py` | `results/dbq/*` | ~2 h |
| Figures | `bash scripts/make_figures.sh` | `figures/` | ~2 min |

The timing experiments (`c1_sampler.py`, `c4_same_schedule.py`, `dbq_run.py`) should run on an otherwise idle machine.

## Notes

- **Parameter rule.** For every $K$ with $K^2>(N+1)\epsilon^2/(8\gamma)$, $\zeta$ is the largest multiple of $10^{-7}$ for which
  the MSE bound of Theorem 2 meets the target $2(1+\gamma)/\epsilon^2$; the radii follow the radius equation, and the $K$ with
  the fewest bytes per user is selected. Every selected point is checked with `mpmath` interval arithmetic. The selection is
  optimal only within this rule.
- **Randomness.** Seeds are fixed in the scripts, so reruns reproduce the stored results up to timing.
- **Timing.** All parties of a method run in one process on one machine; the database workload sends every message over a
  rate-limited loopback TCP connection and does not model latency or loss.
- **Baselines.** GKMPS uses the explicit formulas of its Theorems 2, 8 and 10–12; its numerical parameter search is not
  reproduced, so its communication is an upper bound. ID-Sum is our adaptation of LNF to summation. GKMPS, BBGN and ID-Sum are
  compared analytically on communication and have no cryptographic implementation here.
- **Sampler.** The sampler uses double-precision arithmetic; the privacy theorems assume exact sampling over the reals.
- `b3_e2e.py` and `s1_gkmps_kappa.py` are used as libraries by `pu_e2e.py` and `c2_comm.py`.
